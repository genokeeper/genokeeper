- **Found:** 2026-11-02, while checking SpliceAI's renamed genes: SLC37A4 (carrier Tier 3) has no row
  in `resources/coverage/cds.GRCh38.tsv`.
- **Where:** the packaged MANE cuts (`coverage/cds.GRCh38.tsv`, `deletions/exons.GRCh38.tsv`),
  `evidence.predicted.failed_gate` (gates 2 and 3), and the `genome-ask` skill.

Why the row is missing: MANE v1.5 places SLC37A4's only transcript (ENST00000642844.3) on
`chr11_KN196481v1_fix`, a GRC fix patch, and both cuts keep the primary chromosomes only (their
`SOURCE.md` files say so). The callers run on the primary assembly (`GRCh38_no_alt`, no fix
patches), so nothing that needs the MANE model can use it. What that breaks, consumer by consumer:

- **Predicted findings.** VEP 116's cache holds SLC37A4's transcripts on chr11 with no MANE flag
  (read from the cache file `11/119000001-120000000.gz`: ENST00000642844 is absent, and none of
  the gene's transcripts sits beside a `MANE_Select` value), and UCSC's NMD Escape track lists the
  MANE transcript on the fix patch only (3 rows on `chr11_KN196481v1_fix`). So every predicted
  loss of function in SLC37A4 fails gate 2 (`2 transcript: not on MANE Select or MANE Plus
  Clinical`) and goes under research. The skill tells the agent to call a gate-failed prediction
  doubtful "for that reason", which here describes the assembly, not the variant: a real
  truncation in a Tier 3 gene would never reach the carrier topic, and would be described as
  doubtful. A missed finding, never a false one.
- **Per-gene coverage.** No row, so `query --gene SLC37A4` reads `not measured`; the skill says to
  report that. Honest, without a reason.
- **Deletions and copy number.** Not screened; already named (`carrier.py`'s not-covered text,
  `deletions/SOURCE.md`).
- **SpliceAI.** Unaffected: SpliceAI's own annotation holds SLC37A4 on chr11 by name.
- **ClinVar claims and the calls.** Unaffected: DeepVariant calls chr11, and ClinVar's GRCh38
  coordinates are the primary assembly's.

The skill's Coverage section says SLC37A4 "is not covered" as a whole, which overstates it: its
variants are called and its ClinVar claims graded.

**Evidence.** The cache and track reads above (by reading the lab's public annotation files, no
run); `tests/test_skill_contract.py::test_skill_names_the_annotation_limits` fails on this branch
before the change (`AssertionError: SLC37A4`: the Predicted findings section never names it).

**Suggested fix (a hypothesis):** no packaged or lab file holds a MANE model of SLC37A4 on the
primary assembly, and none can: MANE defines it on the fix patch. The only full fix is to call on
a reference that carries `chr11_KN196481v1_fix` (a small download), which changes the reference
and so every step key from alignment on. Short of that, name the limit where the reader meets
it: the skill's Predicted findings (a gate-2 failure in SLC37A4 says nothing of the variant) and a
Coverage sentence that says what is and is not covered. Must not change: the LoF gates, which fail
closed. Alternative: treat a primary-assembly SLC37A4 transcript as MANE, which would emulate
MANE's choice on a sequence MANE did not choose.

**What this evidence does not establish:** whether a real run carries a predicted LoF in
SLC37A4.

## Fix

Partial: the limit is named where a reader meets it; the limit itself stays.

The skill's Predicted findings now say that SLC37A4's only MANE transcript lies on a GRC fix
patch, so a predicted loss of function there always fails LoF gate 2 and that failure says nothing
of the variant (a clinical lab can assess it). Its Coverage section names what is not covered for
SLC37A4 (coverage, deletions, copy number) and that its variants and ClinVar claims are called and
graded, instead of calling the gene uncovered as a whole. Covered by
`tests/test_skill_contract.py::test_skill_names_the_annotation_limits` and the reworded assertion
of `test_skill_covers_deletions`. Not changed: the LoF gates (they fail closed), the packaged MANE
cuts, any step key.

Left open, priced: the only full fix is to call on a reference that carries
`chr11_KN196481v1_fix`. The patch sequence is a small download, but it changes the reference, so
every step key from alignment on moves and the user's reads and the calibration libraries are
aligned again; the owner decides whether that is worth one gene.
