- **Found:** 2026-11-02, while checking SpliceAI's renamed genes: SLC37A4 (carrier Tier 3) has
  no row in `resources/coverage/cds.GRCh38.tsv`.
- **Where:** the packaged MANE cuts (`coverage/cds.GRCh38.tsv`, `deletions/exons.GRCh38.tsv`),
  `evidence.predicted.failed_gate` (gate 2), `annotate.vep.parse_vep` (no MANE row to prefer),
  and the `genome-ask` skill.

Why the row is missing: MANE v1.5 places SLC37A4's only transcript (ENST00000642844.3) on
`chr11_KN196481v1_fix`, a GRC fix patch, and both cuts keep the primary chromosomes only (their
`SOURCE.md` files say so). The callers run on the primary assembly (`GRCh38_no_alt`, no fix
patches), so nothing that needs the MANE model can use it. What that breaks, consumer by consumer:

- **Predicted findings.** VEP 116's cache holds SLC37A4's transcripts on chr11 with no MANE flag
  (read from the cache file `11/119000001-120000000.gz`: ENST00000642844 is absent, and none of
  the gene's transcripts sits beside a `MANE_Select` value); VEP's cache holds the MANE transcript,
  flagged, under `HG2217_PATCH`, which no call reaches, as UCSC's NMD Escape track lists it on
  the fix patch only (3 rows on `chr11_KN196481v1_fix`; gate 2 stops a record before gate 3
  reads it). So every predicted loss of function in SLC37A4 that passes gate 1 fails gate 2
  (`2 transcript: not on MANE Select or MANE Plus Clinical`) and goes under research. A start-loss
  fails gate 2 too, before gate 4 ("start-loss: never a finding"), which every gene with a MANE
  row reaches. The skill tells the agent to call a gate-failed
  prediction doubtful "for that reason", which here describes the assembly, not the variant: a
  real truncation of the main transcript in a Tier 3 gene would never reach the carrier topic,
  and would be described as doubtful. And with no MANE row, `parse_vep` grades the variant's most
  severe consequence on any SLC37A4 transcript, so another transcript's loss of function can hide
  the main transcript's missense. Missed findings, never false ones.
- **Compound heterozygotes.** `promote._hets` pairs a predicted research statement only when its
  reason names no failed LoF gate, so an SLC37A4 predicted loss of function is never paired with a
  second heterozygous variant in the gene; in CFTR the same two make a candidate pair.
- **Per-gene coverage.** No row, so `query --gene SLC37A4` reads `not measured`; the skill says to
  report that. Honest, without a reason.
- **Deletions, insertions and copy number.** Not screened: their targets are the MANE exon cut
  (`deletions.exons.load_exons`); named for deletions and copy number already (`carrier.py`'s
  not-covered text, `deletions/SOURCE.md`).
- **SpliceAI.** Unaffected: SpliceAI's own annotation holds SLC37A4 on chr11 by name.
- **ClinVar claims and the calls.** Called and graded on chr11, ClinVar's GRCh38 coordinates
  being the primary assembly's. The primary sequence carries an extra C in the gene's exon
  (chr11:119027726-7). gnomAD v4.1 holds `GRCh38:chr11:119027725:AC:A` at a filtering allele
  frequency of 0.998, and ClinVar 20261011 classifies it Benign/Likely benign ("no sequence
  alteration"): nearly every genome is called homozygous for this deletion, which restores
  MANE's sequence. Traced per path, it makes no misleading statement: ClinVar grades it a
  non-finding (benign); the predicted path never sees it (ClinVar classifies it, so
  `clinvar_vids` holds it); `genotype --gene SLC37A4` lists it as two copies of a Benign allele
  with its benign reason, as any common benign allele. Every chr11 model of the gene bridges the
  extra base with a 1-bp intron at chr11:119027725, MANE's c.528 (so their CDS reads Trp176
  where MANE's reads Cys176), and so a rare change at that base, such as ClinVar's unclassified
  missense `119027725 A>C`, reads intronic to VEP and is never graded as a missense.

The skill's Coverage section says SLC37A4 "is not covered" as a whole, which overstates it: its
variants are called and its ClinVar claims graded.

**Evidence.** The cache and track reads above (by reading the lab's public annotation files, no
run); `tests/test_skill_contract.py::test_skill_names_the_annotation_limits` fails on main's
skill (the Predicted findings section never names SLC37A4).

**Suggested fix (a hypothesis):** no packaged or lab file holds a MANE model of SLC37A4 on the
primary assembly, and none can: MANE defines it on the fix patch. Name the limit where the reader
meets it: the skill's Predicted findings (gate 2 alone is no reason to call an SLC37A4 loss of
function doubtful; it cannot be judged on the primary assembly) and a Coverage sentence that says
what is and is not covered. Telling the main transcript's copies on chr11 apart by a hand list of
transcripts would emulate MANE's choice: several chr11 transcripts carry the main protein's CDS.
Must not change: the LoF gates, which fail closed. Alternatives: treat a primary-assembly SLC37A4 transcript as MANE for gate 2, or cut a non-MANE
primary model into the coverage and exon tables; either would emulate MANE's choice on a sequence
MANE did not choose and break the tables' MANE contract. Calling on a reference that carries the
fix patch is no cheap way out (see the Fix).

**What this evidence does not establish:** whether a real run carries a predicted LoF in
SLC37A4.

## Fix

Partial: the limit is named where a reader meets it; the limit itself stays.

The skill's Predicted findings now make SLC37A4 an exception to the gate-failure rule, for a loss
of function: its only MANE transcript lies on a GRC fix patch, so a predicted loss of function past
gate 1 always fails gate 2, which alone is no reason to call it doubtful: it cannot be judged on
the primary assembly, and a clinical lab can assess it. They say such a prediction is never paired
as a possible compound heterozygote, that a start-loss there is worded as everywhere else (never a
finding), and that another transcript's loss of function can hide the main transcript's missense.
A second bullet explains the near-universal `GRCh38:chr11:119027725:AC:A` call as the standard
sequence and says a rare change at MANE's c.528 is never graded as a missense. Its Coverage
section names what is not covered for SLC37A4 (coverage, deletions, insertions, copy number) and
that its variants and ClinVar claims are called and graded against the primary sequence. Covered by
`tests/test_skill_contract.py::test_skill_names_the_annotation_limits` and the reworded assertion
of `test_skill_covers_deletions`. Not changed: the LoF gates (they fail closed), the packaged MANE
cuts, any step key.

Left open: no full fix is established. Calling on a reference that carries `chr11_KN196481v1_fix`
would need, beyond the patch sequence: ALT-aware alignment (the patch duplicates the region, so a
plain aligner splits its reads at MAPQ 0 and degrades the chr11 calls), shards on the patch contig
for the callers that run per primary chromosome (DELLY, Dysgu), a contig-name map to VEP's
`HG2217_PATCH`, new MANE cuts, and every step key from alignment on moved, with the user's reads
and the calibration libraries aligned again. Not worth one gene without the owner's say.

The dashboard and `genokeeper explain` then still showed an SLC37A4 predicted loss of function's
stored reason as it was, "failed LoF gate 2 transcript: not on MANE Select or MANE Plus Clinical",
which a reader may take as "not on the gene's main transcript"; the limit was named for the agent
only.

Fixed (the second change): the reason now comes from the data, for every gene VEP holds no MANE
transcript of on the primary assembly, not SLC37A4 alone. The suggested anchor, a gene with no
row in the packaged MANE cut, would not have fixed the class: the cut holds only the coverage
genes, while gate 2 decides for every ClinGen haploinsufficient and recessive gene. The anchor is
VEP's own MANE flags, the ones gate 2 already reads: `annotate.vep.parse_vep` sets
`VepRecord.gene_mane`, whether any row of the record's Ensembl gene, at any of the run's
variants, is MANE Select or MANE Plus Clinical (rank-0 rows of genes outside `keep`, never held,
included). It is per gene, not per site: a minor isoform's exon more than VEP's 5 kb from the
MANE transcript has no MANE row at its own variants, yet the gene has MANE rows at the genome's
other variants, so its LoF keeps `GATE_TRANSCRIPT`. `failed_gate` returns `GATE_NO_MANE` ("2
transcript: no MANE transcript of the gene on the primary assembly, so the prediction cannot be
judged") in place of `GATE_TRANSCRIPT` when the record is off MANE and its gene has none, and
`GATE_START_LOSS` for a start-loss there, as on a MANE transcript. The skill's exception is now
that reason, with SLC37A4 named as the gene whose LoF past gate 1 always reads so.
`VEP_STEP_VERSION` is 8: the VEP step's records carry the new field.

Covered by `tests/test_vep.py::test_vep_record_says_whether_its_gene_has_mane` (no MANE row of
the gene, another gene's MANE row at the site, the gene's rank-0 MANE row before and after its
minor isoform's stop, and its MANE row at another variant only), the two `GATE_NO_MANE` and
start-loss cases of `tests/test_predicted.py::test_lof_gates`, and the reworded
`tests/test_skill_contract.py::test_skill_names_the_annotation_limits`.

Not changed: the gate fails closed as before, and the reason still starts `failed LoF gate`, so
such a prediction stays under research and is never paired as a possible compound heterozygote
(`promote._hets`). The packaged MANE cuts, and so SLC37A4's coverage, deletions, insertions and
copy number, stay as above; a reference carrying the fix patch stays the owner's call.
