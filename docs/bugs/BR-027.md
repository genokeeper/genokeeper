- **Found:** 2026-11-02, while checking SpliceAI's renamed genes: SLC37A4 (carrier Tier 3) has
  no row in `resources/coverage/cds.GRCh38.tsv`.
- **Where:** the packaged MANE cuts (`coverage/cds.GRCh38.tsv`, `deletions/exons.GRCh38.tsv`),
  `evidence.predicted.failed_gate` (gates 2 and 3), and the `genome-ask` skill.

Why the row is missing: MANE v1.5 places SLC37A4's only transcript (ENST00000642844.3) on
`chr11_KN196481v1_fix`, a GRC fix patch, and both cuts keep the primary chromosomes only (their
`SOURCE.md` files say so). The callers run on the primary assembly (`GRCh38_no_alt`, no fix
patches), so nothing that needs the MANE model can use it. What that breaks, consumer by consumer:

- **Predicted findings.** VEP 116's cache holds SLC37A4's transcripts on chr11 with no MANE flag
  (read from the cache file `11/119000001-120000000.gz`: ENST00000642844 is absent, and none of
  the gene's transcripts sits beside a `MANE_Select` value), and UCSC's NMD Escape track lists the
  MANE transcript on the fix patch only (3 rows on `chr11_KN196481v1_fix`); VEP's cache holds the
  MANE transcript, flagged, under `HG2217_PATCH`, which no call reaches. So every predicted loss
  of function in SLC37A4 that passes gate 1 fails gate 2 (`2 transcript: not on MANE Select or
  MANE Plus Clinical`) and goes under research. The skill tells the agent to call a gate-failed
  prediction doubtful "for that reason", which here describes the assembly, not the variant: a
  real truncation of the main transcript in a Tier 3 gene would never reach the carrier topic,
  and would be described as doubtful. And with no MANE row, `parse_vep` grades the variant's most
  severe consequence on any SLC37A4 transcript, so another transcript's loss of function can hide
  the main transcript's missense. Missed findings, never false ones.
- **Per-gene coverage.** No row, so `query --gene SLC37A4` reads `not measured`; the skill says to
  report that. Honest, without a reason.
- **Deletions, insertions and copy number.** Not screened: their targets are the MANE exon cut
  (`deletions.exons.load_exons`); named for deletions and copy number already (`carrier.py`'s
  not-covered text, `deletions/SOURCE.md`).
- **SpliceAI.** Unaffected: SpliceAI's own annotation holds SLC37A4 on chr11 by name.
- **ClinVar claims and the calls.** Called and graded on chr11, ClinVar's GRCh38 coordinates
  being the primary assembly's, against the primary sequence, which differs from MANE's at one
  coding base: c.528 (chr11:119027726, reference C on the plus strand), Trp176 on the primary
  sequence and Cys176 in MANE, as the two CDSs in VEP's cache read. A call there is relative to
  the primary base.

The skill's Coverage section says SLC37A4 "is not covered" as a whole, which overstates it: its
variants are called and its ClinVar claims graded.

**Evidence.** The cache and track reads above (by reading the lab's public annotation files, no
run); `tests/test_skill_contract.py::test_skill_names_the_annotation_limits` fails on this branch
before the change (`AssertionError: SLC37A4`: the Predicted findings section never names it).

**Suggested fix (a hypothesis):** no packaged or lab file holds a MANE model of SLC37A4 on the
primary assembly, and none can: MANE defines it on the fix patch. Name the limit where the reader
meets it: the skill's Predicted findings (gate 2 alone is no reason to call an SLC37A4 loss of
function doubtful; its transcript says whether it truncates the main one) and a Coverage sentence
that says what is and is not covered. Must not change: the LoF gates, which fail closed.
Alternatives: treat a primary-assembly SLC37A4 transcript as MANE for gate 2, or cut a non-MANE
primary model into the coverage and exon tables; either would emulate MANE's choice on a sequence
MANE did not choose and break the tables' MANE contract. Calling on a reference that carries the
fix patch is no cheap way out (see the Fix).

**What this evidence does not establish:** whether a real run carries a predicted LoF in
SLC37A4.

## Fix

Partial: the limit is named where a reader meets it; the limit itself stays.

The skill's Predicted findings now make SLC37A4 an exception to the gate-failure rule: its only
MANE transcript lies on a GRC fix patch, so a predicted loss of function past gate 1 always fails
gate 2, which alone is no reason to call it doubtful; on ENST00000545985 (the chr11 copy of MANE's
NM_001164277.2) it truncates the main transcript and a clinical lab can assess it, on another
transcript it is doubtful as any off-MANE one; and another transcript's loss of function can hide
the main transcript's missense. Its Coverage section names what is not covered for SLC37A4
(coverage, deletions, insertions, copy number) and that its variants and ClinVar claims are called
and graded against the primary sequence, which differs from MANE's at one coding base. Covered by
`tests/test_skill_contract.py::test_skill_names_the_annotation_limits` and the reworded assertion
of `test_skill_covers_deletions`. Not changed: the LoF gates (they fail closed), the packaged MANE
cuts, any step key.

Left open: no full fix is established. Calling on a reference that carries `chr11_KN196481v1_fix`
would need, beyond the patch sequence: ALT-aware alignment (the patch duplicates the region, so a
plain aligner splits its reads at MAPQ 0 and degrades the chr11 calls), caller shards on the patch
contig (every caller runs per primary chromosome), a contig-name map to VEP's `HG2217_PATCH`, new
MANE cuts, and every step key from alignment on moved, with the user's reads and the calibration
libraries aligned again. Not worth one gene without the owner's say.
