- **Found:** 2026-10-28 (whole-repository review; reproduced 2026-11-02)
- **Where:** `src/genokeeper/refresh.py`, `run_needed` and `GRADING_INPUTS`.

`run_needed` runs the pipeline only for a new analyser or a downloaded grading input
(ClinVar, gene validity, CGD, CPIC, PharmGKB, GWAS, ClinGen dosage, GenCC) whose newest file
differs from the latest snapshot's. The tables the lab builds itself are not compared: the
calibration tables `genokeeper calibrate` writes (`calibrate.tables.TABLES`) and the gnomAD
FAF table (`genokeeper build-faf`). After the owner calibrates, a `genokeeper refresh` with no
new upstream release runs nothing, and the store, the dashboard and the skill keep reading
"not calibrated" until a manual `genokeeper run`.

**Evidence.** On main at f81626d, `tests/test_refresh.py`'s
`test_a_new_calibration_table_decides_a_run` (for `small_variants`, `stage3` and `slice3f`)
and `test_a_rebuilt_faf_table_decides_a_run` each fail at their last line, `assert
refresh.run_needed(lab.lab, latest, IDENTITY)`, after the table on disk changed: 4 failed.

**Suggested fix (a hypothesis):** let the run record each calibration table's
`versions.json` sha256 and let `run_needed` compare those and the FAF manifest's sha256 (which
the run already records) with the files on disk. `calibrate` rewrites a table only when it is
stale, so a new table always has another `versions.json`. Must not change: MedlinePlus and
the publication sources never trigger a run. Alternative: print a hint and leave the run to
the owner; it needs the same detection and still leaves the store stale.

**What this evidence does not establish:** how often the owner calibrates without running
`genokeeper run` afterwards.

## Fix

A run records each calibration table's `versions.json` (`run.inputs["tables"]`, through
`calibrate.tables.versions_files`, read before any table is opened), and `run_needed` compares
`refresh.LAB_TABLES` (that record and the FAF manifest the run already recorded) with the
files on disk, as it compares the downloaded grading inputs. Covered by
`tests/test_refresh.py::test_a_new_calibration_table_decides_a_run`,
`test_a_rebuilt_faf_table_decides_a_run`, and the end-to-end run in
`tests/test_pipeline_invariants.py::test_run_genome_end_to_end`, which checks the run records
each lab table as refresh reads it. Not changed: no step key; MedlinePlus and the publication
sources still never trigger a run; VEP's and the PRS files stay out (pinned downloads, not
tables the lab builds). Bound: a table that turns current without being written again (its
versions computable once the bootstrap supplies a missing file) is not seen; the next run
picks it up.
