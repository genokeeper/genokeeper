- **Found:** 2026-10-28 (whole-repository review; reproduced 2026-11-02)
- **Where:** `src/genokeeper/pipeline.py`, `repeat_steps` (the `repeats` step's key) and the
  other step keys.

Three suspected defects in the step keys:

1. Over-keyed: the `repeats` key hashes every `[repeat_loci]` row whole
   (`asdict(locus)`: its note, evidence, topic, rule, validity and disease thresholds), while
   its build reads three fields: `locus_id` and `variant_id` (which catalog entry, which
   region) and `normal_max` (which loci REViewer draws). An edit to any other field re-runs
   ExpansionHunter, REViewer and the flank ratio on the run and on every stage-3 calibration
   sample, for the same output.
2. Under-keyed: the native samtools (the flank ratio's `bedcov`, mito's `view`, Scramble's
   `view -M`) was thought to be in no key.
3. Over-keyed: sex and the FASTA sha sit beside keys that already hold them.

**Evidence.** On main at f81626d, `tests/test_pipeline_invariants.py`'s
`test_repeats_step_keyed_on_what_its_build_reads` fails at `assert
reused["steps"]["repeats"]["reused"]` after a rerun whose grading changes HTT's note, evidence
and `pathogenic_min` (with a stage-3 table measured under that grading, which the run
requires). For (2), by reading: every cached step that runs native samtools holds
the align step's key (`cram_key` is `steps["align"].key`, or for the calibration's spike-in a
hash over it), and `align_step`'s key holds `versions["samtools"]`. For (3), by reading:
each repeated part changes only together with the key that holds it.

**Suggested fix (a hypothesis):** key `repeats` on the three fields its build reads. Must
not change: any input that changes a step's output stays in its key. (2) and (3) need no
change: a samtools upgrade already re-runs those steps through the align key, and a repeated
part adds no rerun of its own; dropping one would move the DeepVariant call key (about 21 h a
library) for nothing.

**What this evidence does not establish:** how long ExpansionHunter's pass takes on the
owner's run.

## Fix

The `repeats` key holds, of each `[repeat_loci]` row, `locus_id`, `variant_id` and
`normal_max` (`repeat_steps`), the fields its build reads. Covered by
`tests/test_pipeline_invariants.py::test_repeats_step_keyed_on_what_its_build_reads` (a note,
evidence and threshold edit reuses the step; a `normal_max` edit runs it again). Parts 2 and
3 do not reproduce on main and are left as they are, by the trace under Evidence. The
`repeats` key moves once: the next run, and each stage-3 calibration sample, runs
ExpansionHunter, REViewer and the flank ratio again. No other step key moves.
