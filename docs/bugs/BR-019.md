- **Found:** 2026-10-29 (before a rerun of the owner's pipeline)
- **Where:** `src/genokeeper/containers.py`, `build_inputs_digest` and `main` (a built
  image's tag ends with the sha256 of its build inputs), and the step keys that hold
  `IMAGES[name]` (the VEP step holds `IMAGES["spliceai"]`).

A built image's tag hashes its Dockerfile and lock files byte for byte, comments included. A
step whose key holds that tag runs again after any edit to them, even one that changes no
installed file. A change that re-wrote only the comments of
`docker/spliceai.requirements.txt` (its compile command and `# via` lines) moved the
`spliceai` tag, so the next `genokeeper run` would have rebuilt the image and run SpliceAI
again (about 4.5 h, README) for the same pins and the same output; that change was backed
out before the rerun. Six built images have comment lines in a lock file (aldy, bcyrius,
spliceai, rbceq2, fastmixture, hmmix); the conda `.lock` files have none, and haplogrep3's
`.yaml` is a configuration file the image installs as it is, not a lock file.

**Evidence.** On main at f81626d, `tests/test_containers.py`'s
`test_a_comment_only_lock_edit_keeps_the_image` (a reworded header comment, a blank line and
every `# ` widened in spliceai's and hmmix's lock files) fails for both: `containers.main`
refuses the build ("docker/ holds other inputs than … was named for"), so the stub `docker`
is never called and the check of its calls fails.

**Suggested fix (a hypothesis):** hash a lock file without its full-line comments and blank
lines (never a Dockerfile, whose `# syntax=` line matters; never a `#` inside a line, which in
a conda lock carries the md5). Must not change: an edit to a pin, a hash or a Dockerfile
instruction still names another image. Hashing that way moves the tags whose lock files carry
comments once; the alternatives keep today's tags valid until each image's next real change,
with or without a pinned comment-free digest for each.

**What this evidence does not establish:** whether a Dockerfile comment edit should keep
the tag too.

## Fix

`build_inputs_digest` hashes a lock file (`.txt`, `.lock`) without its comment lines and
blank lines (`containers._installed`); a Dockerfile and a copied configuration file
(haplogrep3's `.yaml`) stay whole, and a `#` inside a line stays. Covered by
`tests/test_containers.py::test_a_comment_only_lock_edit_keeps_the_image` (spliceai, hmmix:
a comment edit builds the pinned name, a pin edit is refused),
`test_inputs_digest_moves_with_any_installed_input` (a requirements pin and a conda md5 still
move the digest) and `test_built_images_named_by_their_inputs`.

The six tags move once (aldy, bcyrius, spliceai, rbceq2, fastmixture, hmmix); the fourteen
conda-only tags and haplogrep3's do not. After this change `scripts/bootstrap.sh` builds the
six images again (a run before it is refused, Docker having no image of that name), and the
next run re-runs the steps keyed on them: VEP with SpliceAI and the predicted genotypes keyed
on it, the pgx callers (aldy, bcyrius) and aldy's CYP2A6 paralog step, blood groups,
ancestry and the archaic segments. On the calibration side, the slice 3f typing steps of
each library and `slice3f_truth_rbceq2` re-run, and a `paralogs` or `slice3f` table already
measured turns stale (its versions name aldy, or rbceq2, fastmixture and hmmix) until
`genokeeper calibrate` measures it again.

Bound: a comment or blank line inserted right after a pip line ending in `\` would end that
line's continuation without moving the digest; no lock file under docker/ has one, and pip's
hash-checking mode then refuses the build rather than installing something else.
