- **Found:** 2026-11-02 (a full-suite run on GitHub's runner; reproduced the same day)
- **Where:** `tests/test_calibrate_hg002.py` (the `download` and `fetch_one` tests) and
  `tests/test_calibrate_realign.py`, through `src/genokeeper/calibrate/records.py`,
  `need_space`, which reads `shutil.disk_usage`.

`need_space` refuses unless the folder's disk has what a file needs plus `MARGIN_BYTES`
(20 GB) free. That is the production guard, and it is right. The tests that drive a download
or a re-alignment through it never stub the probe, so they pass or fail with the free space
of the machine running them: on a runner with 12 GB free each one raises `RunRefused: …
needs 20 GB free in …, 12 GB is`. A re-run on another runner passed, so the failure reads as
a flake.

**Evidence.** On GitHub's runner, a full-suite run failed in `test_calibrate_hg002.py`'s
`test_download_*` tests and `test_calibrate_realign.py` with that message; its second attempt,
on another runner, passed. On this Mac at 8a88393, the suite run with a pytest plugin that
makes `shutil.disk_usage` report 12 GB free (`uv run pytest -q -n auto -p <plugin>`): 18
failed, 2579 passed, 4 skipped. The failures are 15 in `test_calibrate_hg002.py` (12
`test_download_*` cases, `test_chunks_and_connections_give_one_output`,
`test_cut_stream_lands_nothing_and_keeps_the_raw` and
`test_fetch_one_keeps_pairs_and_deletes_raw`) and 3 in `test_calibrate_realign.py`
(`test_cram_to_fastq_round_trips`, `test_realign_count_mismatch_refuses`,
`test_realign_replaces_the_old_cram_and_clean_frees_it`). `shutil.disk_usage` has no other
caller in `src/`, and no test reaches `need_space` in a subprocess.

**Suggested fix (a hypothesis):** stub the probe for every test (an autouse fixture making
`shutil.disk_usage` report ample space), and keep the test that drives the refusal with a low
stubbed value. Must not change: `need_space` and its margin. Alternative: stub it only in the
two modules; a later test elsewhere that reaches `need_space` would then depend on the host
again.

**What this evidence does not establish:** whether other host-dependent reads (free memory,
CPU count) fail the suite on a small runner.

## Fix

An autouse fixture in `tests/conftest.py`, `ample_free_disk`, makes `shutil.disk_usage` report
1 TB free in every test, so no test reads the host's disk.
`tests/test_calibrate_hg002.py::test_download_refuses_without_free_space` still stubs 5 bytes
free and drives the refusal through `download` and `downsample_fastq`. Covered by the same
plugin run as under Evidence, now green, by
`test_calibrate_hg002.py::test_a_test_never_reads_the_hosts_free_disk` (the stub is in
effect; red without the fixture), and by that refusal test. Not changed: `need_space`, `MARGIN_BYTES` and every production caller.
