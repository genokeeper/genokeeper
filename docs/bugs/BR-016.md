- **Found:** 2026-10-27 (seen once during a wrapper run; reproduced 2026-11-02)
- **Where:** `src/genokeeper/containers.py`, `run_container`'s `DockerUnavailable`.

When `docker run` exits 125, the message quotes the first non-blank stderr line. With the
core gate (`tools.GATE`, used whenever it exists) the gate's own notice can come first, so the
reader takes a gate notice for the reason Docker could not start the image, while Docker's
error is further down. Taking the last line instead is no fix: Docker 29.9.2 ends that error
with "Run 'docker run --help' for more information".

**Evidence.** On main at f81626d, `tests/test_containers.py`'s
`test_docker_s_own_error_is_quoted_behind_a_gate` (a gate printing one notice line, then
Docker's three lines, exit 125) fails: the message reads "Docker could not start … (label
dna:qc is not in the weight file): run scripts/bootstrap.sh". Docker's own output for a
missing image and a missing bind source, captured on this Mac the same day: a line starting
`docker: Error response from daemon:`, a blank line, then the `--help` line.

**Suggested fix (a hypothesis):** quote the first line Docker prefixes with `docker:`, else
the first non-blank line. Must not change: the class raised and the bootstrap hint. Do not
model the gate's output to skip it.

**What this evidence does not establish:** that every Docker failure under exit 125 has a
`docker:` line; without one the first line is still quoted.

## Fix

`run_container` quotes the first stderr line that starts with Docker's own `docker:` prefix,
else the first non-blank line. Covered by
`tests/test_containers.py::test_docker_s_own_error_is_quoted_behind_a_gate` and
`test_failed_container_raises_with_its_stderr` (no `docker:` line: the first is quoted). Not
changed: the class raised, the bootstrap hint, and nothing models the gate's output.
