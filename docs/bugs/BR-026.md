- **Found:** 2026-11-02 (after slice 3g-2 added the FUT2 trait)
- **Where:** `src/genokeeper/sources/traits.py` with `resources/traits/traits.tsv`'s FUT2 row
  (`trait:FUT2`, rs601338 alone, validity moderate, not gated by the slice 3f table), and
  `src/genokeeper/sources/bloodgroups.py`, `BloodGroupSource._kind` (`bloodgroup:FUT2`,
  RBCeq2 2.4.4 at the 36 FUT2 rows of `rbceq2_2.4.4_positions.tsv`, 35 positions with
  rs601338 among them, validity limited, gated by the slice 3f table).

Both statements answer one question, secretor status, under the traits topic. Both read the
same calls, so at rs601338 they agree, and with rs601338 A/A RBCeq2 types two null alleles
(HG002's fixture: `FUT2*01N.02/FUT2*01N.02`, `Se-`). They can disagree in one direction: a
FUT2 null or weak allele in RBCeq2's table at another position, carried with rs601338 G/A or
G/G, gives the trait "likely secretor" and the blood group a non-secretor or weak phenotype.
Neither statement names the other, and the skill gives no precedence, so an answer can quote
either. The default view (`query`'s and the dashboard's: validity moderate, reliability
medium) shows the trait alone when its call is graded medium or high, and until a slice 3f calibration exists the blood group is
unassessed ("not calibrated"); the two show side by side only with `--min-validity limited`
once both are findings.

**Evidence.** The tests of the fix, run against `main` at 8a88393's `src/` and skill (the
skill-contract constant inlined); the test run's last lines:

```
FAILED tests/test_bloodgroups.py::test_fut2_finding_names_the_secretor_trait
FAILED tests/test_skill_contract.py::test_skill_answers_secretor_status_from_one_statement
2 failed, 1 passed in 3.19s
```

The one that passes is `test_default_view_shows_the_secretor_trait_alone`, which pins
today's default view.

**Suggested fix (a hypothesis):** keep both statements and have each name the other in words:
a typed `bloodgroup:FUT2` adds "the secretor-status trait reads rs601338 alone; where they
differ, this blood group is the fuller reading"; the trait's note adds that the blood group
is the fuller reading only when it gives a phenotype, never when it reads unassessed or not
calibrated. The skill answers secretor status from `bloodgroup:FUT2` when it is a finding,
otherwise from `trait:FUT2`. Must not change: the default view, and an unassessed blood group
never reads as overriding. Considered: dropping the trait (no secretor answer at all until
slice 3f is calibrated, and none in the default view after), and having the trait read
RBCeq2's call in code (one answer, at about three times the lines and a coupling between two
sources).

**What this evidence does not establish:** which of RBCeq2's FUT2 alleles sit at which of
the 35 positions, or how often the disagreement occurs; no allele table was downloaded.
Settling it needs RBCeq2's `db.tsv` FUT2 rows read against a population's frequencies.

## Fix

`genokeeper/genokeeper#10`. Both statements stay, and each names the other in words:

- A FUT2 blood group typed with a phenotype adds `SECRETOR_TRAIT`
  (`src/genokeeper/sources/bloodgroups.py`). An unassessed FUT2, or one RBCeq2 gave no
  phenotype, adds nothing.
- The trait's FUT2 note (`resources/traits/traits.tsv`) says the blood group is the fuller
  reading only when it gives a phenotype, never while it is unassessed or not calibrated.
- The genome-ask skill has a routing row that reads both by id: `--gene FUT2` never returns the
  blood group, which has no gene. It answers secretor status from `bloodgroup:FUT2` when that
  is a finding with a phenotype, otherwise from `trait:FUT2`, and says which one answered.

Covered by `tests/test_bloodgroups.py`'s `test_fut2_finding_names_the_secretor_trait` and
`test_default_view_shows_the_secretor_trait_alone` (the default view unchanged),
`tests/test_skill_contract.py`'s `test_skill_answers_secretor_status_from_one_statement`, and
`tests/test_traits.py`'s caveat checks.

Deliberately not changed:
- the default view and either statement's validity;
- the trait's rule, which still reads rs601338 alone;
- the code coupling between the two sources, which stays out of scope.

The evidence boundary stands: how often the two disagree is still not measured.
