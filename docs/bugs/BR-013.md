- **Found:** 2026-11-02, carried over from the private history's ledger (a 2026-10-28 review
  finding), reproduced on this tree.
- **Where:** `src/genokeeper/annotate/vep.py`, `parse_vep`'s row key
  `(mane_select and rank > 0, rank, listed, mane_select, mane_plus_clinical)`.

The leading key `mane_select and rank > 0` is compared across every row of the variant, so:

1. A MANE Select missense beats a `stop_gained` on the same gene's MANE Plus Clinical
   transcript, which gate 2 (`record.mane`) would accept as a LoF.
2. Across overlapping genes, gene A's MANE Select missense hides listed gene B's LoF, and an
   unlisted gene's MANE Select LoF outranks a listed gene's MANE Select missense.

The losing row never reaches grading, so a LoF or a listed gene's missense is lost.

**Evidence.** The scratch test of BR-012 on `main` (f81626d) printed, for `keep={"BRCA1"}`:

- case 1 (BRCA1 MANE Select missense, BRCA1 MANE Plus Clinical stop):
  `('GRCh38:chr1:1200:C:T', 'BRCA1', 'ENST01', 'missense_variant')`;
- case 2, first half (GENEZ MANE Select missense, BRCA1 MANE Plus Clinical stop):
  `('GRCh38:chr1:1300:C:T', 'GENEZ', 'ENST09', 'missense_variant')`;
- case 2, second half (GENEZ MANE Select stop, BRCA1 MANE Select missense):
  `('GRCh38:chr1:1400:C:T', 'GENEZ', 'ENST09', 'stop_gained')`.

**Suggested fix (a hypothesis):** case 1 alone is one line (lead with `(mane_select or
mane_plus_clinical) and rank > 0`) but swaps which MANE row is graded rather than grading both;
case 2 needs one record per (vid, gene) and a statement id that names more than the vid, which
reaches the store's primary key, history and `changes`. Must not change: a minor isoform's LoF
never hides the MANE missense. BR-012 is the same seam.

**What this evidence does not establish:** whether any variant of a real run sits in
overlapping genes or on a MANE Plus Clinical transcript.

## Fix

Fixed with BR-012 by one redesign: records per variant and Ensembl gene (two genes sharing a
symbol are two), no row compared across genes,
and in one gene the MANE Select row of interest plus a MANE Plus Clinical row of a higher rank,
so case 1 grades both rows instead of choosing one (no ruling between them was needed). A
variant can now give two statements, so a predicted statement's id is
`predicted:<vid>:<transcript>` (unversioned), which the store's primary key needs; the
accounting counts each graded record once and each other input variant once. Two records of one
variant never make a compound heterozygote (`promote` pairs distinct vids). Every reader of the
id (`query`, `show`, `explain`, the dashboard's search, `changes`, `refresh`) treats it as
opaque; the first `changes` after the change lists each predicted statement once as removed and
added again, and its history starts again there, so its "first found" date becomes that run's
(`history` carries a renamed id across only for `clinvar:` statements). `VEP_STEP_VERSION` is 5.

Covered by `tests/test_vep.py::test_vep_records_per_gene` (`SELECT_AND_PLUS`,
`OVERLAP_PLUS_STOP`, `OVERLAP_MANE_STOP`, `SHARED_SYMBOL`, and `SHARED_EXON` for a Plus
Clinical row of equal rank adding nothing) and `tests/test_predicted.py::test_two_records_of_one_variant_are_two_statements`
(ids, accounting, no pair). Not changed: a minor isoform's LoF never hides a MANE missense.
