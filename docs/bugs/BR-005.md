- **Found:** 2026-11-02
- **Where:** `src/genokeeper/deletions/screen.py`, `warnings`, `exon_hits` and `screen_all`;
  `src/genokeeper/sources/deletions.py`, `_gene_rows`.

Two wording and placement gaps:

1. "read depth does not support it" is said of every short-band deletion (50 to 999 bp)
   whose DELLY depth ratio is not below `max_depth_ratio`, where 150 bp reads often cannot
   move the depth at all. The test is weak there, but the line reads as evidence against
   the call.
2. A target is an exon widened by `exon_margin` (20 bp) on each side, so a deletion that
   touches only that intronic margin is shown, numbered and placed exactly like one that
   removes exon sequence; nothing tells the two apart.

**Evidence.** On `origin/main` at f81626d, hand-built inputs (a script, its output kept;
GENEA's exon 2 is `[2000, 2100)`, its target `[1980, 2120)`):

```
BR-005 short both, no depth: ['read depth does not support it']
BR-005 [1915, 1985) flank only: exons {'GENEA': (2,)}, fields ['call_class', 'deletion', 'exons', 'kinds', 'population']
BR-005 [1915, 2001) exon base: exons {'GENEA': (2,)}, fields ['call_class', 'deletion', 'exons', 'kinds', 'population']
```

**Suggested fix (a hypothesis):** in the short band, a depth line that says depth often
cannot show a deletion this short; a gene reason line where the call touches that gene's
targets only within the margin. Must not change: the call class, and so the calibration,
nor the placement (the margin holds the splice sites, which a deletion there can break).
Alternative: a measured length below which depth is uninformative, which needs HG002's true
deletions' depth ratios by length.

**What this evidence does not establish:** the length at which the depth ratio becomes
informative for this library.
