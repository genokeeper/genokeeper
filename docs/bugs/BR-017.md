- **Found:** 2026-10-28 (stage 3 review; reproduced 2026-11-02)
- **Where:** `scripts/bootstrap.sh`, `step_hg002` and `step_hg004`, and
  `src/genokeeper/calibrate/hg002.py`, `_fetch_command`'s "no recorded bases" refusal.

On a lab without a `genokeeper run`, `fetch` refuses with "no recorded bases for your run:
run genokeeper run first" and the step then dies with "fetching HG002 pcrfree failed; rerun
to continue with the files not yet downsampled". A rerun fails the same way. The steps after
it never run, `step_gnomad_faf` among them, so with `--with-gnomad --with-hg002` the FAF
table the run needs is never built, and `genokeeper run` refuses for want of it. README's
Quick start already tells the owner to leave both flags out before the first run.

**Evidence.** On main at f81626d, `tests/test_bootstrap.py`'s
`test_a_library_fetch_before_a_run_lets_the_bootstrap_go_on` (a `fetch` that refuses as the
real one does, then `echo after`) fails for both steps with exit 1, `after` never printed,
and stderr ending "bootstrap: fetching HG002 pcrfree failed; rerun to continue with the files
not yet downsampled" (HG004's alike).

**Suggested fix (a hypothesis):** let `fetch` exit with its own status before a run recorded
the bases, and let both steps say the libraries wait for that run and return, so the later
steps still run; every other failure still stops the bootstrap. Must not change: the
libraries are downsampled to the owner's recorded bases. Alternative: move `step_gnomad_faf`
before the reference-sample steps; it fixes the FAF case only, and the bootstrap still stops
on a message that asks for a rerun.

**What this evidence does not establish:** the behaviour on a real fresh lab; the test fakes
`fetch`.

## Fix

`python -m genokeeper.calibrate.hg002 fetch` exits `NOT_YET` (3) before a run recorded the
bases, saying "run genokeeper run, then rerun scripts/bootstrap.sh with this flag"; the
bootstrap's `fetch_library` turns that status into one line saying the library waits for the
first run, and `step_hg002` and `step_hg004` return so the later steps (`step_gnomad_faf`
among them) run. Any other status still stops the bootstrap. README's two passages say so.
Covered by `tests/test_bootstrap.py::test_a_library_fetch_before_a_run_lets_the_bootstrap_go_on`
(both steps, status 3 and 2) and
`tests/test_calibrate_hg002.py::test_fetch_before_a_run_says_not_yet`. Not changed: the
downsampling target and the step order.
