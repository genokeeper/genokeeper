- **Found:** 2026-11-02
- **Where:** `src/genokeeper/deletions/screen.py`, `classify`; against
  `src/genokeeper/calibrate/build.py`, `build_insertions`' union cut
  (`d.length >= t.min_length`).

INSurVeyor writes an insertion it could not assemble with neither `SVLEN` nor an assembled
part; the reader gives it no length and marks it a lower bound. The run keeps such a call
(`is_short` never cuts a call of unknown length) and `classify` bands it by `end - pos`,
one base, so it is shown in the `short` band with that band's chance of being false. The
insertion calibration's union cut keeps only calls of `min_length` or more, so no call of
this kind is ever in what that band measured: the rate it is shown with was measured on
other calls.

**Evidence.** On `origin/main` at 8a88393 (a script over a hand-built call, its output
kept):

```
run: screen ({'GENEA': (1,)}, None) class band short length 1
calibration union cut `d.length >= min_length` keeps it: False
```

**Suggested fix (a hypothesis):** give such a call a band of its own, `unsized`, which no
table measures, so the run shows it unassessed (`not calibrated: no unsized calls
measured`) as it does any unmeasured band. Must not change: a Dysgu insertion whose length
is a bound (it has an `SVLEN`), which keeps its length's band, as the calibration measures
it. Alternative: measure these calls by position in the insertion calibration, as Scramble's
lone mobile elements are, in their own band; a looser rule on an unknown number of calls.

**What this evidence does not establish:** how many such calls a run makes.

## Fix

`classify` gives a call of unknown length (no `svlen`, a lower bound) the band `UNSIZED`
(`unsized`), checked after the `mei` return so a Scramble-only call keeps `mei`. No table
measures it, so `p_wrong` is None and the run withholds the call, unassessed with
`not calibrated: no unsized calls measured`. The calibration is unchanged: its union cut
already leaves these calls out. The `genome-ask` skill says how to read one. Covered by
`tests/test_deletion_screen.py::test_unsized_insertion_has_a_band_of_its_own`; the
withholding of an unmeasured band is `tests/test_deletion_source.py::test_unmeasured_band_withheld`.

Not changed: any other call's band, the insertion table, its versions.
