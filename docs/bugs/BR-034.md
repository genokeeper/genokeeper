- **Found:** 2026-11-06 (`genokeeper calibrate --only slice3f` on HG002 PCR-free)
- **Where:** `src/genokeeper/roh.py`, `run_roh`; `src/genokeeper/calibrate/build.py`, `build_roh`.

`build_roh` limited `bcftools roh` to the benchmark through `-T`, and the tool stopped at once:

```
Error: The options --AF-file and -t are mutually exclusive
```

`--AF-file` acts as the targets, so `-t` and `-T` cannot sit beside it, and `-r` and `-R` need an
indexed file, which `write_target_vcf`'s plain gzip is not. `tests/test_roh.py` asserted the
command's words and `tests/test_calibrate_slice3f.py` replaced `run_roh` with a fake, so nothing
ran the two options together.

**Evidence.** The run at 7219934 passed `slice3f_roh` on HG002 PCR-free, HG003 and HG004 with the
masked reference and built the table, exit 0, and the table withholds nothing for ROH. In tests, no
real `bcftools` runs `run_roh`'s command or `inside`'s output: `tests/test_roh.py`'s `tools` test
writes its own command.

**What this evidence does not establish:** that the cut gives the runs the tool's own filter would.
`-R` on a bgzipped, indexed copy is accepted beside `--AF-file`, and matched the cut on one
synthetic file only, not on the three libraries. Nor how a run on the owner's data behaves: it is
not cut to any benchmark, passes no targets, and was not rerun here.

## Fix

`inside(vcf, bench, out)` in `src/genokeeper/roh.py` writes the header and the rows inside the
benchmark, as `truth_sites_vcf` already leaves rows out, and `build_roh` hands the cut file to the
`ours` and `spiked` runs. `run_roh` loses its `regions` argument and mount.
`SLICE3F_STEP_VERSION` moves to "2". Covered by
`tests/test_roh.py::test_inside_keeps_the_header_and_the_benchmark_rows` and
`tests/test_roh.py::test_run_roh_command`, which holds that no target option reaches the tool, and
`tests/test_calibrate_slice3f.py::test_roh_compares_three_files_cut_to_one_benchmark`, which holds
that all three runs read files cut to one bed.

The fakes in `tests/test_calibrate_slice3f.py` were not replaced by the real tool. This is the third
ledger entry from this table where a fake hid a tool's contract (BR-032, BR-033), and each was
found by the table's run on real data.
