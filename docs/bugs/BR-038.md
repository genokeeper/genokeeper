- **Found:** 2026-11-08 (reading `genokeeper calibrate --only stage3 --report`'s lines for HG002,
  HG003 and HG004, the table of 2026-11-06)
- **Where:** `src/genokeeper/calibrate/repeat_rules.py`, `RFC1_WITHHELD` and
  `measure_repeat_rules`; latent beside it, `src/genokeeper/calibrate/stage3.py`, `measure`.

RFC1 is rightly withheld, and the owner accepted that. What is wrong is the sentence the table
stores, which a run shows as the statement's `reason`. It says the motif call "was not a clear
normal on a healthy calibration sample". The report shows the opposite on all four samples:

```
RFC1	pcrfree normal (no expanded allele)	pcr normal (no expanded allele)	hg003 normal (no expanded allele)	hg004 normal (no expanded allele)	withheld: not covered: the RFC1 motif call was not a clear normal on a healthy calibration sample
```

The check is that both HG002 libraries see its known benign expanded allele
(`HG002_RFC1 = ("normal", "1 expanded benign allele, 1 short reference allele")`). The calls are
clear normals that miss that allele, so a reader of the reason learns the reverse of what limits
the call: its "normal" did not see an expanded allele that is there. Reproduced from the code on
2026-11-08: `("normal", "no expanded allele") == HG002_RFC1` returned `False`.

**A latent case at the same check.** `measure` writes `FALSE_CALL` whenever `graded_normal` fails,
which assumes HG002 is normal at every locus. HG002's truth at ATXN2 is 22/30 and `normal_max` is
28, so a call that sizes it exactly fails too: `graded_normal(load_grading().repeats.loci["ATXN2"],
(Allele(22, (22, 22), 20, 0, 0), Allele(30, (30, 30), 20, 0, 0)))` returned `False`. On this table
the reason is still true, because PCR-free really was a false call (22/27, interval 26–64, 3 off,
not Mendelian). It would misstate a table on which both libraries size the allele exactly.

**Suggested fix (a hypothesis):** split `RFC1_WITHHELD` into "HG002's benign expanded allele was
not seen" and "a parent was not normal", both in `_ONLY`. The alternative is one sentence covering
both. RFC1 must stay withheld either way. The table stores the sentence, so a fix reaches a run
only when the `stage3` table is rebuilt, and a change to a file the table reads calls for that
rebuild. Until then the genome-ask skill says what the sentence means, and `README.md` states what
was measured.

**What this evidence does not establish:** why the motif analysis missed HG002's allele
(ExpansionHunter's in-repeat read count, the libraries' read length or the catalog's region are
all open), and the allele's presence is taken from `HG002_RFC1` and its citation of GIAB's v5.0q
truth, not checked here. Settling the first needs ExpansionHunter's output for RFC1.
