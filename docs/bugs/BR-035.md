- **Found:** 2026-11-08 (the first `genokeeper run` with slices 3c-3f)
- **Where:** `src/genokeeper/sources/repeats.py`, `_cftr`; `src/genokeeper/query.py`, `OWNS_GENE_CALL`.

`gene_call` has one row per run and gene. Slice 3e's CFTR poly-T/TG writes one under `CFTR`, and
PharmCAT, which calls CFTR too, writes another. The final insert raised, after 39 hours of steps:

```
_duckdb.ConstraintException: Constraint Error: PRIMARY KEY or UNIQUE constraint violation:
duplicate key "<run id>, CFTR"
```

No test ran the PharmCAT source and the repeat source into one store: the pipeline test's PharmCAT
fake reports no CFTR. Keeping the first row would have been worse, since `pharmcat:CFTR` and
`expansionhunter:CFTR` both passed the join, and one would have shown the other's call.

**Evidence.** The names `gene_call`'s five writers use were enumerated from the code: CFTR is the
only one two of them share. The collision follows from those lists, not from any sample's data.
The run's transaction rolled back, so the store holds no part of it.

**What this evidence does not establish:** that the rest of the run's write succeeds; that is
known only once the run is repeated from its cached steps.

## Fix

The tracts' statement and gene call go by `CFTR_CALL` (`CFTR-polyT-TG`), and the statement's `gene`
stays CFTR, so a question about the gene still finds it. `OWNS_GENE_CALL` now joins a gene call to
the statement whose id ends with its name when that name starts with the statement's gene, in the
query, the history and the dashboard. A statement without a gene owns none, so RBCeq2's
`bloodgroup:ABCG2` does not read PharmCAT's ABCG2. Old snapshots read as before, since their names
equal their genes. No schema change.

Covered by `tests/test_repeats_grading.py::test_no_two_sources_write_one_gene_call`, which fails on
any later overlap between the writers' names,
`tests/test_repeats_grading.py::test_cftr_call_is_named_apart_and_stays_under_the_gene`,
`tests/test_query.py::test_two_tools_on_one_gene_read_their_own_gene_calls`,
`tests/test_query.py::test_a_statement_without_a_gene_reads_no_gene_call` and
`tests/test_history.py::test_two_tools_on_one_gene_change_apart`. The dashboard's join has no test
of its own: the only row it would change is one `_screened` leaves out.

The pipeline test's fakes were not widened to run PharmCAT's CFTR beside the repeats. This is the
fourth entry of this wave where a fake hid a failure only a real run showed.
