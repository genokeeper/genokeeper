- **Found:** 2026-11-02
- **Where:** `src/genokeeper/calibrate/deletions.py`, `DeletionTable.cautions` (3b's table
  alone); `src/genokeeper/pipeline.py`, the insertion `DeletionSource` and `CnvSource`;
  `src/genokeeper/cnv/screen.py`, `screen_cnv`'s `Shown`.

BR-002 gave a 3b deletion's call two lines where its chance of being false is extrapolated:
a class the calibration never saw, and a target outside the region the rate was measured
in. Slice 3d's insertion and depth tables are the same class model (`ClassTable`) and
extrapolate the same way, but their calls carry neither line. And BR-005's reason line for
a gene a call touches only in the margin beside its exons is set by the 3b screen alone, so
a depth loss or gain that reaches a gene only there reads like one over its exons.

**Evidence.** On `origin/main` at 8a88393 (a script over hand-built inputs, its output
kept):

```
ClassTable has cautions: False
DeletionTable has cautions: True
CnvSource fields with 'cautions': ['deletion_cautions']
depth loss reaching GENEA only in its 20 bp margin: exons {'GENEA': (2,)} flank frozenset()
```

**Suggested fix (a hypothesis):** move `cautions` to `ClassTable`, record each table's
target parts outside the region each band was measured in, and wire the insertion and cnv
tables' cautions where the run builds their sources; set `flank` on the depth screen's
`Shown`. Must not change: any `p_wrong` value, any call class, any placement. Alternative:
one flat outside list per table, which is wrong for the depth gains, measured genome-wide.

**What this evidence does not establish:** how many insertion or depth calls fall in an
unseen class or outside the benchmark; that needs calibrated tables and a run.

## Fix

`ClassTable.cautions` (moved from `DeletionTable`) gives `UNSEEN` from the table's measured
classes and `OUTSIDE` from `extra["outside_benchmark"]`, now per band:
`classes.outside_benchmark` subtracts from the targets the region each band's geometry was
measured in, so 3b's two bands and the insertion bands get the targets outside the
benchmark (Scramble's `mei` band, outside its scanned part of it), the depth losses those
outside the benchmark, and the depth gains, measured on every primary chromosome, none. The
deletion, insertion and cnv tables' versions name that form (`"extra": OUTSIDE_VERSION`), so
a table written before it is stale. The run hands each table's cautions to its calls
(`pipeline.table_cautions`): the insertion source's, and a new required `CnvSource.cautions`
for its depth events and named depth losses; a large event, shown with no rate, gets none.
`screen_cnv` sets `flank` as `screen_all` does. The `genome-ask` skill says 3d's rows carry
both. Covered by `tests/test_calibrate_classes.py`
(`test_cautions_read_each_bands_own_region`, `test_outside_benchmark_per_band`),
`tests/test_calibrate_build_slice3d.py` (`test_large_withheld_recorded`,
`test_scramble_meis_judged_by_position`, which holds each insertion band's list),
`tests/test_calibrate_deletions.py`
(`test_cautions_name_an_unseen_class_and_a_target_outside_the_benchmark`, and
`test_calibrate_deletions_writes_a_table_the_run_accepts` for both of 3b's bands),
`tests/test_cnv_source.py::test_depth_events_carry_the_cnv_tables_cautions`,
`tests/test_cnv_screen.py::test_depth_event_over_a_flank_only_named` and, for the run's
wiring, `tests/test_pipeline_invariants.py::test_calibrated_slice3d_statements`, whose
patched `cautions` names the table it was called on, so a swap of the cnv and insertion
tables' cautions fails it.

`mei`'s region (the benchmark within 500 bp of a target) and the benchmark give the same
outside list, as every target base lies within 500 bp of itself: the two differ only off the
targets, where no call is shown, so no test can tell them apart there; the test holds that
the three insertion bands' lists are equal.

Not changed: any `p_wrong` value, class or placement. The deletion table's `extra` changes
form (one list per band), so a 3b table measured under PR 5's flat list is stale too; none
has been measured.
