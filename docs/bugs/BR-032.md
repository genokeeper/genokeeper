- **Found:** 2026-11-06 (`genokeeper calibrate --only slice3f` on HG002 PCR-free)
- **Where:** `src/genokeeper/genotype/gvcf.py`, `calls_at` and `normalise`;
  `src/genokeeper/pipeline.py`, `build_sites` in `typing_steps`.

Slice 3c moved the lab's reference to GRCh38 with the GRC false duplications masked to N.
`normalise` runs `bcftools norm -c e`, and its docstring read a mismatch as the wrong FASTA. A
resource's allele inside a masked block holds a real base where the FASTA has N, so one such
allele stopped everything in its `calls_at` call. The user sees the whole step fail.

The calibration stopped on two errors. One was the admixture step's:

```
fastmixture failed: exit 255: Reference allele mismatch at chr13:86265157 .. REF_SEQ:'N' vs VCF:'G'
```

The other, on ROH's sites, hid the same crash behind a missing folder, because `build_sites`
passed `out / "scratch"`, which nothing had made:

```
ROH failed: [Errno 2] No such file or directory: '.../roh_sites/.building-6b9aa7f9/scratch/.norm-el7ixlvm'
```

`tests/fixtures/genome_mini.py` did not catch the folder because `FakeTyping` replaces
`sites_vcf` with a stub, `tests/test_calibrate_slice3f.py` does the same, and
`tests/test_roh.py` stubbed `roh.calls_at` and passed a folder that exists.

**Evidence.** Sites of the public resources inside the 12 masked intervals (1,237,765 bp),
counted against `masked_intervals.GRCh38.tsv`. An AF file and `pruned.bim` hold HGDP+1kGP's
sites, and no masked row of either holds an N in its REF:

| resource | sites | in the mask | what reached `calls_at` |
|---|---|---|---|
| each ROH AF file | not counted | 2,042 rows | all, unfiltered |
| `pruned.bim` | 417,469 SNPs | 102 | all, unfiltered |
| PharmCAT 3.4.0 positions | 1,288 alleles | 0 | none in the mask |
| RBCeq2 positions | 1,119 items | 0 | none in the mask |
| HLA tags, traits, UGT1A1*28 | 34 alleles | 0 | none in the mask |
| ClinVar GRCh38 20261011 | not counted | 5 records | none: `-c x` drops them first |
| GWAS Catalog 20261022 | 987,893 | 0 | none in the mask |
| 45 PGS scoring files | 41,598,460 rows | 3 | none: `target_positions` drops them |

`bcftools norm -c e` 1.24 on a scratch FASTA with an N run: `G>A` and a reference-only `G>.`
on an N stop with exit 255, as does `TA>T` with its second base on an N; `N>.` and `TN>T`
pass; and `TT>T` right after the run left-aligns to `NT>N` with exit 0.

**Suggested fix (a hypothesis):** leave a masked allele unknown in `calls_at` and keep `-c e`
for the rest. Must not change: a truly wrong FASTA stopping the run. Considered: `-c x`, as
the ClinVar build uses, with a dropped allele read as unknown, which would make a wrong FASTA
look like a run of unknowns.

**What this evidence does not establish:** whether the call layer's other callers can meet a
masked allele with future resources; today only ROH and admixture do. The counts describe the
release of each resource in the lab on the day they were taken, so a new release can move them.
The mask's ROH sites are counted, not their effect: whether writing 2,042 sites as no-calls
changes a run's boundaries is unmeasured.

## Fix

`calls_at` checks each allele's reference span against `load_mask()`, in the contig name it
resolved, and answers an overlap with `MASKED_REASON` before `normalise`. That reason starts
`genotype unknown`, as `query` requires, and travels as `NO_COVERAGE_REASON` does. Traced side
by side through `grade_called`, the calibration's level, `site_genotype`, `write_target_vcf`,
`write_pharmcat_vcf`, `risk_copies` and the JSON round trip, both give low, `./.`, None and an
equal `Called`. Nothing in `src/` keys on either constant's text; `mito.py` uses
`NO_COVERAGE_REASON` for chrM alone. `genokeeper.masking` imports without a cycle.

`normalise` makes `scratch`, and `graded` and the slice 3f calibration no longer do, so one
rule holds for every caller.

Covered by `tests/test_gvcf.py::test_allele_in_a_masked_block_is_unknown`, on the real
`bcftools norm`, `tests/test_gvcf.py::test_ref_mismatch_outside_a_masked_block_stops` (on a
base and on an N the mask does not list) and
`tests/test_roh.py::test_sites_vcf_makes_its_scratch_folder`. With the check removed:

```
E   Reference allele mismatch at chr1:2999 .. REF_SEQ:'CGN' vs VCF:'CGT'
FAILED tests/test_gvcf.py::test_allele_in_a_masked_block_is_unknown - genokee...
1 failed in 5.44s
```

Deliberately not changed: no step version moves. A masked allele used to stop its step unless
its REF held an N, and none of the shipped resources' masked alleles does, so no step that
finished changes. The other readers of the FASTA stay as they are: ClinVar's and PharmGKB's
`-c x` and `target_positions` still drop an allele at a masked position, and GWAS's `locate`
counts one as `reference_differs`. gnomAD's table is built on the unmasked FASTA. `-c e` itself
stays.

The boundary above still stands: no `genokeeper calibrate` or `genokeeper run` went with this
fix, so the failing step's second run has not been observed.
