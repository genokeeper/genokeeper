- **Found:** 2026-11-09
- **Where:** `scripts/bootstrap.sh` `step_panelapp`

The panel's sha256 was taken on the bytes of one fetch, and the API does not return the same bytes
twice, so the bootstrap refused the version it pins and the PanelApp layer did not run.

Evidence: `bootstrap: sha256 mismatch for https://panelapp.genomicsengland.co.uk/api/v1/panels/285/?format=json, not panel 11.93`
in the run of 2026-11-09. Two more fetches that minute, both `version` 11.93 of 2026-11-06 with 2,867
genes and 2,765,735 bytes, had different sha256s. Parsed and compared gene by gene, they differ only in
the order of `evidence` for 2 genes, KCNQ5 and SLC6A19.

**What this evidence does not establish:** that `evidence` is the only unordered list over more fetches.
A later fetch that differs elsewhere would be refused and would say so, with the layer not run.

## Fix

`step_panelapp` sorts each entity's `evidence` and writes the file with sorted keys before it takes the
sha256, and the pin is of that form; both fetches above give the same digest. A response that is not
JSON is refused like a mismatch. Covered by `tests/test_bootstrap.py::test_panelapp_panel_pinned_by_sha256`.
Deliberately not changed: the URL, which is the live panel the owner approved, so a later version is
refused until the pin moves.
