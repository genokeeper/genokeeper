- **Found:** 2026-11-02, the part of BR-012 left open.
- **Where:** `src/genokeeper/annotate/vep.py`, `annotate`, which matches SpliceAI's scores to
  VEP's records by `(vid, VEP's SYMBOL)`.

SpliceAI 1.3.1 writes one entry per gene of its bundled GRCh38 annotation (GENCODE v24, 2016),
named as GENCODE named it then. VEP 116 names genes as HGNC does now. A listed gene renamed since
gets no SpliceAI score, so a splice change in it never reaches the splice rule: a missed finding,
never a false one.

Which genes: the genes SpliceAI is run on (ACMG SF v3.3 and carrier Tier 3, 190) were compared
with SpliceAI 1.3.1's `annotations/grch38.txt`, copied from the local SpliceAI image offline
(sha256 565c0ea83f66b2210182364c3d626fef526229e3d02f444bab247329b6695f2c). 185 are named there.
Of the five that are not, four are renames whose every MANE Select CDS exon (the packaged
`coverage/cds.GRCh38.tsv`, MANE v1.5) lies in exactly one annotation gene: ELP1 (IKBKAP), G6PC1
(G6PC), GBA1 (GBA) and MMUT (MUT). The fifth, PLP1, has no gene of the annotation at its exons,
so SpliceAI scores nothing there under any name.

**Evidence.** `tests/test_vep.py::test_spliceai_score_of_a_renamed_gene` on this branch before
the fix: VEP's rows name the gene MMUT, SpliceAI's entry names it MUT, and every record's
`spliceai` was None (`assert {None} == {0.3}`).

**Suggested fix (a hypothesis):** a pinned table of those four old names, read where the score
is matched, so a record looks up SpliceAI's entry under its gene's old name. Must not change: a
record never takes another gene's entry (the review of BR-012 rejected the fallback to a
variant's only entry for that). Alternatives: run SpliceAI on a custom annotation built from
VEP's own release (changes every score, and needs files the lab does not hold), or match through
HGNC's previous symbols (a download).

**What this evidence does not establish:** whether a real run has a splice-scored variant in one
of the four genes.
