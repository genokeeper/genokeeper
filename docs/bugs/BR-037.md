- **Found:** 2026-11-08 (reading the `insertions` calibration summary, public HG002 libraries)
- **Where:** `src/genokeeper/calibrate/classes.py`, `measure` (`h` is the mean of
  `Geometry.reach(L) / region_bp`); `src/genokeeper/calibrate/build.py`, `build_insertions`,
  which hands `measure` each call's `d.length` through `judge_library`.

An insertion is a point: `Deletion.end` is `pos + 1`, and at run time it touches a target "as a
base would" (`deletions/screen.py`, module docstring). `measure` still widens every target by the
inserted length, as it should for a deletion, which spans those reference bases. So the bands
`short` and `long` of the `insertions` table overstate `h`, the chance that a false call touches
a target. The `mei` band is right: Scramble's calls have no `svlen`, so their length is 1.

The summary shows it (`genokeeper calibrate --only insertions --report`, 2026-11-06):

```
short band: h 0.000701, prior 0.00583
long band: h 0.00299, prior 0.00552
```

3b's `deletions` table, whose events do span their length, has `short band: h 0.000665` on the
same targets. The inflation, from this repository's exon resource alone (`Geometry.reach(n)` on
`targets(load_exons(), 20)`, its ratio to `reach(1)`, measured with a one-off script):

```
n     reach(n)  ratio
1     1197715   1.0
50    1394575   1.16
150   1748730   1.46
999   4062363   3.39
1000  4064582   3.39
5000  9172162   7.66
```

The grade cannot move. Overstating `h` raises `p_wrong`, so the error is on the cautious side;
the lowest insertion class measures 0.998, false calls hundreds of times likelier than true ones,
and reading "likely" (`[deletions] likely_below`, 0.1) needs them nine times less likely than true
ones, so `h` would have to be thousands of times lower. What moves is the number in `false_call_rate` and its interval, and only in the
third decimal or later for the short band.

**Suggested fix:** a hypothesis: have `measure` read a length that says how far the event reaches
along the reference, 1 for `short` and `long` insertions, with the versions of the `insertions`
table changed so the table is re-measured. Must not change: the geometry of deletions and depth
events, which do span their length, and the length bands of the truth events, which still sort
by inserted length. The alternative is to keep the overstatement and name it, since no grade
depends on it; a rebuild of the table costs hours, so the fix fits the next rebuild for another
reason.

**What this evidence does not establish:** the size of the error in each band. `h` averages over
the false calls' lengths, the table keeps only the mean, and the benchmark's size is not in the
summary, so `reach(L)` at the mean length is a bound's shape and not a measurement. Settling it
means re-measuring the table with the fix and comparing `h` and every class's `p_wrong`.
