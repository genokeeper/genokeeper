- **Found:** 2026-11-02
- **Where:** `src/genokeeper/calibrate/classes.py`, `ClassTable.p_wrong`;
  `src/genokeeper/deletions/screen.py`, `warnings`; `src/genokeeper/sources/deletions.py`,
  the call's `warnings`.

`p_wrong` returns a value for any call class: the naive-Bayes product of the per-feature
shares, whether or not the calibration had a single call of that class. The table's `measured`
lists the classes each library had, but nothing a shown deletion carries tells the owner or
the `genome-ask` skill that its class had none. Likewise the rates are measured inside GIAB's
v5.0q benchmark regions, while the target exons include ones the benchmark leaves out, many
in segmental duplications; a deletion there takes the inside rate with no line saying so
(the masked feature names segmental duplications, not the benchmark).

**Evidence.** On `origin/main` at f81626d, a hand-built `DeletionTable` whose only measured
long-band class is `long:both+depth:norepeat:unmasked:nojunction` (a script, its output
kept):

```
BR-002 class seen in calibration: long:both+depth:norepeat:unmasked:nojunction p_wrong (0.625, 0.4098360655737705, 0.8064516129032259)
BR-002 class never seen: long:delly:norepeat:unmasked:nojunction p_wrong (0.625, 0.4098360655737705, 0.8064516129032259) warnings ['found by one caller (DELLY)', 'read depth does not support it']
BR-002 DeletionTable has cautions: False
```

The run reads no benchmark BED and the table records none, so no code path could say a
target lies outside it.

**Suggested fix (a hypothesis):** a warning `no calibration call of this class` read from
`measured`'s classes, and one for a deletion over a target part outside the benchmark, the
parts recorded by the calibration in the table's `extra` (the run does not need the BED).
Must not change: the `p_wrong` values themselves. Alternative: withhold `p_wrong` for an
unseen class, which hides a rate the features do support.

**What this evidence does not establish:** how many shown deletions fall in an unseen class
or outside the benchmark; that needs a count on a calibrated run.

## Fix

`DeletionTable.cautions` gives `no calibration call of this class: its chance of being false
is extrapolated` when no library's `measured` classes hold the call's class, and `over a target
outside the benchmark the chance of being false was measured in` when the deletion's bases
touch a target part outside the benchmark. `build_deletions` records those parts in the
table's `extra` (`outside_benchmark`), so the run reads no BED. `DeletionSource.cautions`
puts the lines after the class's warnings; the run wires the deletion table's.
`deletion_versions` names the `extra` key, so a table measured without it is stale rather
than read as all inside the benchmark. Covered by `tests/test_calibrate_deletions.py`
(`test_cautions_name_an_unseen_class_and_a_target_outside_the_benchmark`,
`test_calibrate_deletions_writes_a_table_the_run_accepts`,
`test_versions_leave_out_the_wording_rule`),
`tests/test_deletion_source.py::test_cautions_join_the_class_warnings` and, for the run's
wiring, `tests/test_pipeline_invariants.py::test_calibrated_deletions_statements`.

After the final review: a named locus over a 3b deletion (`cnv:named:*`) shows the deletion
table's chance of being false, so its call carries the same cautions: `CnvSource` takes the
deletion table's (`deletion_cautions`, required, so the run cannot leave it out) and applies
them to a named 3b deletion's row alone, never to a depth event's, which the cnv table rates.
Covered by `tests/test_cnv_source.py::test_named_3b_deletion_carries_the_deletion_tables_cautions`.
The outside-benchmark line there has a limit: the table records only the targets' parts
outside the benchmark, so a named locus off the exon targets is never told it lies outside
it, whether it does or not.

Not changed: the `p_wrong` values, and `h`. Read again, `h` is not the defect it looked
like: the false calls per genome are counted inside the benchmark, so `h` times them is a
false-call density per benchmark base times the targets' genome-wide reach, the same
extrapolation outside the benchmark the new line names; the clamp at 1 only matters for
calls of chromosome scale. The insertion and depth tables' rows carry no such line yet.
