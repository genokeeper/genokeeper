- **Found:** 2026-10-28 (slice 3a's re-review), carried over from the private archive's
  ledger and reproduced on `main` at `f81626d` on 2026-11-02.
- **Where:** `src/genokeeper/calibrate/stage3.py` (`measure`, `truth_repeats`, `report`),
  `src/genokeeper/calibrate/repeat_rules.py` (`measure_repeat_rules`'s `graded`) and
  `config/grading.toml` (`[repeats] min_allele_reads`).

Three gaps in how the stage-3 table is measured:

1. `measure` ignores ExpansionHunter's `LowDepth` filter on HG002, so a locus a run would
   leave unassessed for low depth still counts as measured and kept. The trio checks have the
   same shape: `measure_repeat_rules` grades a low-depth call as if it were not, so a parent's
   low-depth normal validates an exclusion-only rule the run would never grade there. The
   table also records the allele counts without their intervals, while `graded_normal`
   withholds by the interval's upper bound, so the report shows a withheld locus with
   normal-looking counts and no reason visible.
2. In the one-motif slop before a repeat region, `truth_repeats` reads a record's filter and
   genotype before asking whether the record changes any length: a filtered record or a
   flanking SNV there returns "no truth", so the locus escapes the size cap.
3. `min_allele_reads = 4` cites the stage-3 calibration of 2026-10-28 on catalog `57789eab`,
   STRchive's regions; the packaged catalog is now Illumina's, so the threshold was derived
   on other regions, and the table measures nothing it could be re-derived from.

**Evidence.** Four tests, run on `main` at `f81626d` before any fix (pytest's output):


The first uses HG002's real ExpansionHunter output (`tests/fixtures/hg002`) with one call
flagged low depth; the third, a hand-written GIAB-shaped VCF with an SNV two bases before
HTT's region.

**Suggested fix (a hypothesis):** (1) withhold a low-depth HG002 locus with its own reason,
grade a low-depth trio call unassessed, and record and print the intervals; (2) skip a slop
record that ends before the region and changes no length, before its filter and genotype are
read; (3) record each allele's reads in the table and print the fewest per library, so the
next calibration re-derives `min_allele_reads` on the packaged catalog. Must not change: a
locus HG002 fails stays withheld; a filtered record inside the region, or a slop indel that is
not whole motif units, still gives no truth. Alternative for (3): a calibration that refuses
when the configured value exceeds the fewest reads measured; it would refuse nothing on a
healthy sample, whose alleles are all normal.

**What this evidence does not establish:** whether any of the three changes today's table, or
what `min_allele_reads` the Illumina regions give; the stage-3 calibration on HG002, HG003 and
HG004 (`genokeeper calibrate --only stage3`, then `--report`) settles both.

## Fix

- `measure` withholds a locus that is low depth on either HG002 library (`LOW_DEPTH`; a
  false call on either library names the false call, and `repeat_rules.WITHHOLD_ORDER` ranks
  `LOW_DEPTH` after `NO_CALL` and `FALSE_CALL` when the tables merge). `measure_repeat_rules`
  grades a low-depth trio call unassessed, as `RepeatSource` does, with the shared
  `sources.repeats.LOW_DEPTH_REASON`: a repeat locus's call, RFC1's motif call (HG002's
  benign allele is not "seen" at low depth) and CFTR's tracts (HG002's at low depth withhold
  CFTR `LOW_DEPTH`). Tests:
  `tests/test_calibrate_stage3.py::test_measure_withholds_a_low_depth_locus`,
  `tests/test_calibrate_repeat_rules.py::test_a_low_depth_normal_validates_nothing` and
  `test_low_depth_rfc1_and_cftr_validate_nothing`.
- `truth_repeats` skips a record that ends before the region and changes no length before
  reading its filter or genotype; a filtered record in the region and a slop indel that is
  not whole units still give no truth.
  `tests/test_calibrate_stage3.py::test_truth_repeats_skips_a_flank_record_that_changes_no_length`.
- The table records each allele's interval (`ci`) and, at a standard-rule locus, its reads
  (`reads`), and `report` prints the intervals and "fewest reads behind an allele" per
  library over the standard-rule loci the table keeps, the scope `min_allele_reads` was
  derived on (a withheld locus is graded by no run).
  `tests/test_calibrate_stage3.py::test_report_shows_intervals_and_fewest_reads`.
- `stage3.FORMAT` is 4, so a table measured before these (format 3) is not used
  (`test_stage3_table_of_an_earlier_format_not_used`).

Not changed: `min_allele_reads` stays 4. Its comment in `config/grading.toml` now says it was
derived on STRchive's regions and is re-derived from the report's new line in the stage-3
calibration (`genokeeper calibrate --only stage3 --report`), which also settles whether these
changes move today's table.
